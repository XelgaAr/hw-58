# Публикация работы 58

## Подготовка отдельного репозитория

Папка проекта должна быть корнем репозитория: `package.json`, `src`, `scripts` и `.github` находятся рядом. Не загружайте внешнюю папку `projects` как часть репозитория.

Создайте пустой репозиторий в GitHub. Из папки этой работы выполните команды, заменив `USERNAME` и `REPOSITORY`:

```bash
npm install
git init -b main
git add .
git commit -m "Initial project"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Команды Git выполняются владельцем проекта. Существующий репозиторий повторно инициализировать не нужно. Перед добавлением файлов проверьте свои незавершённые изменения. Созданный после `npm install` файл `package-lock.json` следует хранить в репозитории. При последующих установках используйте `npm ci`.

## GitHub Pages

Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Затем **Actions → Check and deploy to GitHub Pages → Run workflow → main**. Последующие push в `main` запускают проверки и публикацию автоматически.

Workflow использует Node.js 24, устанавливает зависимости, проверяет синтаксис, запускает нативные и исходные Vitest-тесты, собирает сайт и проверяет его через Playwright под `/repository-check/`. Только после успешных проверок публикуется `dist`. Для pull request выполняются проверки без публикации. HTML-отчёт, скриншот Vitest и результаты браузерных проверок доступны в артефакте `verification-reports`.

Страницы используют относительные ссылки и не требуют изменения имени репозитория в исходниках. Поддерживаются адрес проекта `https://USERNAME.github.io/REPOSITORY/` и пользовательский сайт `https://USERNAME.github.io/`.

После успешного workflow внесите реальный адрес в раздел «Демо» README. Репозиторий и сайт не считаются опубликованными, пока workflow не завершился успешно.

## Что именно публикуется

На Pages работает интерактивное демо Web Crypto. Исходные функции `node:crypto` остаются в `src/main.js` и запускаются в Node.js. Во время сборки ими вычисляются контрольные значения `vectors.json`; кнопка на странице сравнивает их с результатами браузера. Векторы содержат только явно тестовые строки, а не введённые пользователем пароли.

## Частые проблемы

- **404 сразу после публикации:** проверьте успешность workflow и наличие `index.html` в опубликованном артефакте. Не выбирайте публикацию исходной папки `src`.
- **Нет Pages в настройках:** проверьте доступность Pages для типа репозитория и тарифного плана; для учебной сдачи обычно используется публичный репозиторий.
- **Workflow сообщает об ошибке:** откройте конкретный шаг и исправьте указанную причину; не отключайте проверки ради деплоя.
- **npm не может получить пакеты:** проверьте интернет, DNS и доступ к `registry.npmjs.org`. Основной код, нативные тесты и сборка не требуют npm-зависимостей.
- **Не установлен браузер:** выполните `npx playwright install chromium`. На Linux для системных зависимостей используется `npx playwright install --with-deps chromium`.
- **Web Crypto недоступен:** используйте HTTPS или localhost. Не открывайте HTML двойным щелчком из файловой системы.
